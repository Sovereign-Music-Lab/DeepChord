# 자료에서 피아노 스케치까지: 방법과 검증

[English](methodology.md) · **한국어**

현재 버전은 독립 작성한 공개 이론·코드 기초 RAG도 기본 제공합니다. [기초 자산과 지속 세션](foundation.ko.md)에서 배포 자료·반복 주문·운영체제 범위를 확인하세요. 아래 PDF 준비 절차는 선택적인 개인 교재 제공자에 관한 안내입니다.

이 문서는 현재 코드가 수행하는 일과 사람이 확인할 일을 연결합니다. 설치 명령은 [README](../README.ko.md), 어댑터 학습은 [학습 안내](training.ko.md), 파일 전달은 [Logic 안내](logic.ko.md)를 참고하세요.

## 1. 개인 PDF를 검색 가능한 근거로 준비

DeepChord에는 PDF 수집기, OCR 엔진, 검색 색인 생성기나 교재가 포함되지 않습니다. 별도의 개인 로컬 라이브러리를 준비하고 아래 인터페이스로 연결합니다. 권리가 있는 자료를 사용하고, 원본·OCR·악보 이미지·발췌·색인은 공개 저장소 밖에 둡니다.

권장 준비 순서는 다음과 같습니다. 이는 외부 라이브러리의 구축 절차이며 DeepChord 명령이 자동으로 수행하는 기능이 아닙니다.

1. 책마다 고유한 `source_id`, 제목, PDF의 SHA-256, 전체 페이지 수를 기록합니다. 인쇄 쪽수와 PDF 순번의 대응을 확인하고, 서로 다른 책의 같은 페이지 번호를 구분합니다. 기존 출처를 다른 PDF로 덮어쓰지 않습니다.
2. 페이지 단위로 기존 텍스트와 읽을 수 있는 이미지를 추출합니다. 이미지 전용 PDF의 빈 텍스트는 정상적인 관측 결과입니다. 한국어·영어 OCR은 별도로 보관하며 엔진, 페이지 번호, 행 좌표와 텍스트 신뢰도를 남깁니다.
3. 악보의 코드 기호·임시표·음자리표·음표·리듬이 필요한 부분은 실제 이미지를 확인합니다. 문자 OCR은 OMR이 아니며 OCR 신뢰도는 음표 정확도가 아닙니다. 코드 사전의 목차 위치 확인도 해당 악보 전체를 전사한 것과 다릅니다.
4. 원문 OCR, 검토한 개념·위치 안내, 편집자가 제안한 적용, 새로 작곡한 음표를 구분합니다. 카드에는 출처 ID, 페이지, 이미지 경로, 검토 범위와 한계를 붙입니다. 두 화음의 분수 표기와 단일 슬래시 베이스, 감3화음과 감7화음처럼 혼동하기 쉬운 표기는 따로 확인합니다.
5. 페이지·카드를 검색 문서로 만들고, 한글 띄어쓰기와 코드 기호·영어 별칭을 보완합니다. BM25와 문자 n-gram TF-IDF를 조합할 수 있으며 임베딩은 필수가 아닙니다. 여러 책을 합칠 때는 책별 근거와 검색 ID를 유지합니다.
6. 전체 페이지의 파일·해시·쪽수 대응을 검사하고, 미리 정한 질의의 기대 개념·출처·페이지와 비음악 질의의 결과 없음 처리를 확인합니다. 실제 확인한 사례 수와 악보 대조 범위를 기록합니다. 작은 회귀 검사를 보편적 정확도나 완전한 교재 습득으로 표현하지 않습니다.

## 2. DeepChord에 개인 라이브러리 연결

```sh
export MUSIC_RAG_ROOT=/path/to/private/library
# 외부 제공자의 인터페이스를 먼저 확인:
python "$MUSIC_RAG_ROOT/scripts/rag.py" query '피아노 코드 전위' \
  --top 3 --kind concept --context
# 같은 제공자를 DeepChord에서 사용:
deepchord rag '피아노 코드 전위'
```

현재 `core.retrieve`는 공개 기초 근거를 먼저 준비하고 설정한 루트의 `scripts/rag.py`를 현재 Python으로 실행하고 위의 `query TEXT --top 3 --kind concept --context` 인자를 전달합니다. 제한 시간은 30초이며 표준 출력 문자열을 근거로 사용합니다. 제공자가 실패하면 오류를 반환하며 성공한 검색처럼 조용히 대체하지 않습니다. 연결하지 않으면 공개 기초 RAG만 사용하고 책의 근거를 사용하지 않았다는 문구를 기록합니다.

이 인터페이스를 구현하는 외부 제공자는 여러 책을 내부에서 검색할 수 있습니다. DeepChord가 `--book`을 전달하거나 PDF를 자동 발견하는 것은 아닙니다. `concept` 결과에는 검토한 이론 카드뿐 아니라 명확히 표시한 목차 위치 카드도 포함할 수 있으나, 위치 안내를 음표 전사로 표현하면 안 됩니다. 표준 출력에는 책·페이지·이미지·검토 상태와 해당 질의의 설명을 포함하고, 검색 결과가 없으면 그 사실을 명시하세요. 제공자 로그는 표준 오류로 보내세요.

검색 점수는 정확도 확률이 아닙니다. 상위 세 근거에 실제 요청과 무관한 내용이 있는지 읽고, 책의 원칙을 사용자의 장르·편성·밀도에 맞게 적용합니다. RAG 연결은 모델 가중치를 변경하지 않습니다. [LoRA 학습](training.ko.md)은 검토한 별도 예제·데이터 분리·학습·평가가 필요한 다른 단계입니다.

## 3. 로컬 모델이 음표를 만들고 코드가 검사

```sh
deepchord compose '간결한 4마디 C장조 피아노 리프, 마지막 Cmaj7' \
  --bars 4 --model YOUR_INSTALLED_LOCAL_MODEL
```

Ollama 경로는 설치된 모델의 메타데이터를 확인하고 클라우드 모델을 거부합니다. `--adapter`는 별도의 로컬 MLX 모델·어댑터 경로를 사용합니다. 요청에는 원래 프롬프트와 검색 근거를 넣고, 외부 근거는 지시문이 아닌 참고 데이터로 표시합니다. 교재의 선율을 복제하지 않는 오리지널 피아노 스케치를 요청합니다.

생성 명령은 1–16마디, 4/4 스케치를 받습니다. JSON은 `title`, `tempo`, `bars`, 마디마다 하나의 `chords`, `tracks`를 담으며 음표는 `pitch`, `start`, `duration`, `velocity`를 사용합니다. 음높이는 실음 MIDI 번호(C4=60), 시작·길이는 곡 처음을 0으로 한 4분음표 박입니다. 프롬프트는 `Melody`와 `Accompaniment` 두 피아노 파트, 기억할 동기, 강약·쉼과 자연스러운 연결을 요구합니다. 범용 검사기는 1–3트랙과 최대 32마디를 허용하지만 이것이 생성 명령의 범위를 확장하지는 않습니다.

검사기는 유한한 수치, 피아노 음역 21–108, 벨로시티 1–127, 양의 길이, 형식 안의 종료와 트랙 내 동일 음높이 겹침을 확인합니다. 기본 생성 프롬프트의 코드 기호는 `maj`, `m`, `maj7`, `maj9`, `m7`, `m9`, `7`, `9`, `13`, `6`입니다. `Accompaniment`의 마디별 구성음을 해당 코드 집합과 대조하고 3도·해당 7도를 검사합니다. 이 제한된 비교는 성부 진행·연주 가능성·창작 품질을 판정하지 않습니다. 요청한 보이싱이 현재 코드 어휘 밖이라면 악보의 모든 기호가 지원된다고 가정하지 마세요.

잘못된 출력에는 오류를 돌려 한 번 수정하도록 요청합니다. 두 번 모두 실패하면 작곡 결과로 성공 처리하지 않습니다. `request.json`, 모델 응답, `rag-evidence.txt`는 개인 실행 폴더에 남고, 통과한 결과에는 `composition.json`, `validation.json`, `composition.mid`, `ARRANGEMENT.txt`가 추가됩니다. 일부 실패 결과에는 이 최종 파일들이 없을 수 있습니다. 기본 저장 위치는 README를 참고하세요.

## 4. 연주 표현과 Logic 전달

MIDI 출력은 PPQ 480, 마디별 코드 마커와 피아노 프로그램 힌트를 사용합니다. CC64는 각 마디에서 해제·재페달하며 마지막에 0으로 종료합니다. 현재 이는 출력기의 고정 정책이고 모델이 생성한 세밀한 페달 연주가 아닙니다. 피아노 파트별 음 길이·쉼과 벨로시티는 원본 JSON에 보존됩니다. JSON에는 독립적인 컨트롤러 배열이 없으므로 Logic에서 수정한 페달을 보존하려면 해당 MIDI/프로젝트도 별도로 저장하세요. JSON에서 다시 내보내면 이 고정 페달 정책으로 재생성됩니다.

`deepchord logic open RUN`은 JSON으로부터 새 전체 MIDI를 만들고 macOS에 열기를 요청합니다. 기존 MIDI를 덮어쓰지 않으며 음표 전용 실시간 메시지로 CC64를 잃지 않습니다. 사용자는 Logic의 대화상자를 처리하고 네이티브 피아노·실제 음역·페달·출력을 확인한 뒤 프로젝트를 저장합니다. MIDI의 GM 프로그램 번호는 가져오기 힌트이며 완성 음색이나 악기 배정 확인이 아닙니다.

현재 MCP 연동은 읽기 전용 상태·세션·리전 관측입니다. 자동 악기 선택, 트랙 스택 구성, 플러그인 믹스, 바운스·스템 출력, `.logicx` 저장과 청취는 이 CLI가 완료하는 기능이 아닙니다. Logic 작업을 별도로 진행할 때는 사용자 변경 후 새 프로젝트 상태를 읽고, 멜로디·역할·라우팅·뮤트/솔로와 MIDI/오디오 중복 재생을 확인합니다. 정렬된 스템·믹스는 실제 렌더 후 파일과 재생 경로를 확인해야 합니다. MIDI 수정이 이미 렌더한 오디오에 자동 반영되지는 않습니다.

## 5. 완료를 판단하는 근거

| 단계 | 확인할 근거 | 그것만으로 증명하지 않는 것 |
|---|---|---|
| 자료 준비 | 출처 해시·페이지 대응·OCR 파일·이미지·검토 기록 | 모든 악보의 음표와 리듬을 인식했다는 주장 |
| 검색 | 관련 출처·페이지, 결과 없음 처리, 회귀 질의 | 모델 학습 완료 또는 작곡 품질 |
| 작곡 검사 | JSON·지원 코드 검사·MIDI 이벤트 검사 | 듣기 좋은 곡·연주 가능한 운지 |
| Logic 열기 요청 | `logic-handoff.json`의 요청 수락 상태 | 해당 프로젝트에 실제로 가져오기 완료 |
| 실제 세션 확인 | 새 프로젝트·리전·컨트롤러·악기·저장 경로 관측 | 소리의 청취 평가 |
| 오디오와 청취 | 존재하는 렌더, 레벨·스테레오 점검, 별도의 실제 청취 | 측정만으로 전문 음악 품질 보증 |

CLI는 열기 요청이 성공해도 `import_verified`와 `audio_verified`를 false로 둡니다. 청취 가능한 경로가 없다면 직접 듣지 않았다고 기록합니다. 사람의 피드백을 남긴 뒤 MIDI와 별도 렌더를 수정하고, 학습에 쓸 예제는 다시 검토하세요.

## 재현 확인과 공개 범위

```sh
python -m unittest discover -s tests -v
python scripts/check_public.py
python scripts/check_site.py
```

테스트는 코드 동작·경계와 공개 파일을 확인합니다. 별도 외부 라이브러리의 전체 OCR이나 실제 로컬 모델의 음악적 품질까지 검증하지 않습니다. 커밋·푸시에는 일반화한 코드·문서만 포함하고 개인 PDF, OCR, 악보 이미지·카드·검색 근거·색인, 학습 자료, 모델·어댑터, 생성 곡과 개인 설정을 포함하지 않습니다.
